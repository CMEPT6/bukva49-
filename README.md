## 📌 О проекте

Современные большие языковые модели (LLM) хорошо извлекают факты из неструктурированного текста, но ненадежны в качестве финального исполнителя: они подвержены галлюцинациям, ошибкам в арифметике, несоблюдению жёстких лимитов и рекурсивным зацикливаниям.

**BUKVA-49** решает эту проблему за счёт гибридной архитектуры:
* **LLM / интерфейс ввода** извлекает факты из текста в структурированный вид.
* **Детерминированное ядро BUKVA-49** выполняет проверку условий, расчёт математики, выбор оптимума и опечатывает решение неизменяемым криптографическим аудиторским следом (SHA-256).

> **О славянской нотации:** Именование операторов буквами древней азбуки (Азъ, Вѣди, Есть, Мыслите...) используется как авторский семантический DSL. Каждый оператор имеет стандартный инженерный опкод (`INIT`, `KNOW`, `VERIFY`, `REASON`, `COMPARE`, `SYNTHESIZE`, `GROUND`, `SEAL`). В коде и CLI поддерживаются как славянские, так и стандартные английские имена.

## ⚙️ Архитектура матрицы 7 × 7

Операторы распределены по уровням ответственности:

| Уровень | Опкоды | Роль в системе |
|---|---|---|
| **Входной слой** | `INIT`, `AXIOMS`, `KNOW`, `TRANSMIT`, `VALUATE`, `VERIFY`, `PRESENCE` | Инициализация задачи, фиксация правил и верификация входящих данных |
| **Топология данных** | `LIFECYCLE`, `BOUND`, `GROUND`, `MERGE`, `ALIGN`, `THREAD`, `ALERT` | Фильтрация, отсечение по лимитам бюджета и выявление аномалий цен |
| **Аналитический слой** | `PATTERN`, `NORMALIZE`, `REASON`, `INTERNAL`, `OBJECT`, `FREEZE`, `DECLARE` | Точные вычисления в ядре Python, кэширование и фиксация снимков |
| **Фильтрация и правила** | `EMIT`, `ENFORCE`, `TRANSFORM`, `EXPAND`, `AUDIT`, `ROLLBACK`, `ISOLATE` | Проверка контрактов, приведение типов и аудит прозрачности |
| **Селекция** | `TARGET`, `FORMAT`, `INDEX`, `COMPRESS`, `SOLIDIFY`, `AGGREGATE`, `RELAX` | Группировка, агрегация метрик и выбор целевого признака |
| **Оптимизация** | `CROSS`, `MUTATE`, `REFINE`, `PROBE`, `HARMONIZE`, `SEED`, `WEIGH` | Балансировка весов критериев и калибровка равенств |
| **Интегральный финал** | `EXTRACT_KEY`, `DIFF`, `COMPARE`, `SPIRIT`, `SYNTHESIZE`, `FALLBACK`, `SEAL` | Ранжирование, нахождение оптимума и криптографическая подпись SHA-256 |

### Статус реализации операторов:
* **14 активных трансформаторов:** Непосредственно преобразуют состояние, фильтруют и вычисляют оптимум (`KNOW`, `VERIFY`, `REASON`, `EXTRACT_KEY`, `COMPARE`, `GROUND` и др.).
* **7 контрольно-аудиторских:** Проверяют инварианты, детектируют аномалии цен и формируют SHA-256 подпись (`ALERT`, `AUDIT`, `SEAL` и др.).
* **28 контекстно-декларативных:** Фиксируют границы скоупа, веса и неизменяемые снимки.

## 🚀 Быстрый запуск

### Установка (0 внешних зависимостей)

```bash
# Клонирование репозитория
git clone https://github.com/CMEPT6/bukva49-.git
cd bukva49-

# Локальная установка пакета
pip install -e .
```

### Использование конвейера агента

```python
from bukva49 import BukvaAgentPipeline

pipeline = BukvaAgentPipeline()

# Входные предложения поставщиков (включая недобросовестных)
quotes = [
    {"name": "Неофициальный импорт", "price": 42000, "delivery": 12000, "confirmed": False},
    {"name": "Авторизованный дилер", "price": 54000, "delivery": 2500, "confirmed": True},
    {"name": "Склад Партнёр", "price": 52000, "delivery": 6000, "confirmed": True},
]

# Запуск конвейера с обязательной верификацией
state = pipeline.run("Закупка серверов", candidates=quotes)

print(f"Победитель: {state.selected_id}")         # Авторизованный дилер
print(f"Итоговая сумма: {state.best_score} руб.") # 56500
print(f"Печать SHA-256: {state.seal_hash}")       # Криптографическая подпись полного контекста
```

### Командная строка (CLI)

```bash
# Вывести матрицу 7 × 7:
bukva49 matrix

# Запустить эволюционную формулу:
bukva49 run evolved

# Запустить честный бенчмарк:
py -3 honest_benchmark.py
```

## 📊 Честный бенчмарк и сравнение (Ground Truth)

Подробный протокол и методология описаны в [BENCHMARK.md](BENCHMARK.md).

* **Совпадение с эталонной функцией:** 100.0% на 4000 случайных задачах.
* **Производительность:** Прямой код на Python в 3.5–4 раза быстрее интерпретатора FSM (1.6 мкс против 5.5 мкс на задачу). Ценность конвейера — не в сырой скорости, а в **пошаговой воспроизводимости, формализации правил и неизменяемом аудите**.
* **Устойчивость к фальсификации:** Изменение хотя бы 1 рубля или статуса контрагента во входных данных гарантированно ломает контрольную подпись SHA-256.

## ⚠️ Известные ограничения

1. **Зависимость от структурирования:** Конвейер ожидает структурированные данные (JSON, списки словарей) либо текст со стандартным описанием. Неструктурированный текст на естественном языке должен предварительно разбираться LLM или регулярными выражениями.
2. **Линейность графа:** Базовые формулы выполняются строго последовательно. Ветвления и условные циклы реализуются на уровне мета-автомата.
