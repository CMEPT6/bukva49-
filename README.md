## 📌 О проекте

Современные большие языковые модели (LLM) хорошо извлекают факты из неструктурированного текста, но ненадежны в качестве финального исполнителя: они подвержены галлюцинациям, ошибкам в арифметике, несоблюдению жёстких лимитов и рекурсивным зацикливаниям.

**BUKVA-49** решает эту проблему за счёт гибридной архитектуры:
* **LLM / интерфейс ввода** извлекает факты из текста в структурированный вид (`TaskSpecification`).
* **Детерминированное ядро BUKVA-49** выполняет проверку условий, расчёт математики, выбор оптимума и опечатывает решение неизменяемым криптографическим аудиторским следом (SHA-256 / HMAC-SHA256).

> **О славянской нотации:** Именование операторов буквами древней азбуки (Азъ, Вѣди, Есть, Мыслите...) используется как авторский семантический DSL. Каждый оператор имеет стандартный инженерный опкод (`INIT`, `KNOW`, `VERIFY`, `REASON`, `COMPARE`, `SYNTHESIZE`, `GROUND`, `SEAL`). В коде и CLI поддерживаются как славянские, так и стандартные английские имена.

## ⚙️ Архитектура матрицы 7 × 7

Операторы распределены по уровням ответственности:

| Уровень | Опкоды | Роль в системе |
|---|---|---|
| **Входной слой** | `INIT`, `AXIOMS`, `KNOW`, `TRANSMIT`, `VALUATE`, `VERIFY`, `PRESENCE` | Инициализация задачи, фиксация правил и верификация входящих данных |
| **Топология данных** | `LIFECYCLE`, `BOUND`, `GROUND`, `MERGE`, `ALIGN`, `THREAD`, `ALERT` | Фильтрация, отсечение по лимитам бюджета и выявление аномалий цен |
| **Аналитический слой** | `PATTERN`, `NORMALIZE`, `REASON`, `INTERNAL`, `OBJECT`, `FREEZE`, `DECLARE` | Точные вычисления в ядре Python, кэширование и фиксация снимков |
| **Фильтрация и правила** | `EMIT`, `ENFORCE`, `TRANSFORM`, `EXPAND`, `AUDIT`, `ROLLBACK`, `ISOLATE` | Проверка контрактов, приведение типов и аудит прозрачности |
| **Селекция** | `TARGET`, `FORMAT`, `INDEX`, `COMPRESS`, `SOLIDIFY`, `AGGREGATE`, `RELAX` | Группировка, агрегация метрик и выбор целевого признака |
| **Оптимизация** | `CROSS`, `MUTATE`, `REFINE`, `PROBE`, `HARMONIZE`, `SEED`, `WEIGH` | Балансировка весов критериев и калибровка равенств |
| **Интегральный финал** | `EXTRACT_KEY`, `DIFF`, `COMPARE`, `SPIRIT`, `SYNTHESIZE`, `FALLBACK`, `SEAL` | Ранжирование, нахождение оптимума и криптографическая подпись SHA-256 |

### Статус реализации 49 операторов матрицы:
Согласовано с эмпирическим мутационным анализом (подробнее в [BENCHMARK.md](BENCHMARK.md)):
* **12 влияющих на выбор (Decision Drivers):** Непосредственно трансформируют данные, фильтруют по условиям, считают формулу или находят оптимум (`Вѣди`, `Добро`, `Есть`, `Животъ`, `Ѕѣло`, `Мыслите`, `Отъ`, `Ща`, `Еръ`, `Йота`, `Кси`, `Фита`).
* **20 контрольно-аудиторских (Audit & Guardrails):** Фиксируют журнал шагов, проверяют инварианты контрактов и формируют криптографическую печать (`Азъ`, `Боги`, `Глаголи`, `Есмь`, `Земля`, `Иже`, `Ижеи`, `Инить`, `Гервь`, `Како`, `Людие`, `Нашъ`, `Онъ`, `Покои`, `Рѣци`, `Слово`, `Твѣрдо`, `Фѣртъ`, `Пси`, `Ижа`).
* **17 зарезервированных заглушек (Reserved Stubs):** Зарезервированы под расширенные профили (многокритериальная оптимизация, теория игр, квантили). В текущей версии являются no-op заглушками (`Укъ`, `Оукъ`, `Хѣръ`, `Ци`, `Червль`, `Ша`, `Еры`, `Ерь`, `Ять`, `Юнь`, `Арь`, `Эдо`, `Омъ`, `Енъ`, `Одь`, `Ота`, `Ижица`).

## 🚀 Быстрый запуск

### Установка (0 внешних зависимостей)

```bash
# Клонирование репозитория
git clone https://github.com/CMEPT6/bukva49-.git
cd bukva49-

# Локальная установка пакета
pip install -e .
```

### Использование конвейера агента

```python
from bukva49 import BukvaAgentPipeline

pipeline = BukvaAgentPipeline()

# Входные предложения поставщиков (включая недобросовестных)
quotes = [
    {"name": "Неофициальный импорт", "price": 42000, "delivery": 12000, "confirmed": False},
    {"name": "Авторизованный дилер", "price": 54000, "delivery": 2500, "confirmed": True},
    {"name": "Склад Партнёр", "price": 52000, "delivery": 6000, "confirmed": True},
]

# Запуск конвейера с обязательной верификацией
state = pipeline.run("Закупка серверов", candidates=quotes)

print(f"Победитель: {state.selected_id}")         # Авторизованный дилер
print(f"Итоговая сумма: {state.best_score} руб.") # 56500
print(f"Печать SHA-256: {state.seal_hash}")       # Криптографическая подпись полного контекста
```

## 📊 Честный бенчмарк и сравнение (Ground Truth)

Подробный протокол и методология описаны в [BENCHMARK.md](BENCHMARK.md).

* **Совпадение с эталонной функцией:** 100.0% на 4000 случайных задачах.
* **Производительность:** Прямой код на Python в 3.5–4 раза быстрее интерпретатора FSM (1.6 мкс против 5.5 мкс на задачу). Ценность конвейера — не в сырой скорости, а в **пошаговой воспроизводимости, формализации правил и неизменяемом аудите**.
* **Устойчивость к фальсификации:** Изменение хотя бы 1 рубля или статуса контрагента во входных данных меняет контрольный хеш SHA-256. В режиме HMAC (`secret_key`) гарантируется аутентичность и невозможность подделки без знания секретного ключа; при стандартном открытом SHA-256 защита от подделки обеспечивается внешней фиксацией хеша (в журнале аудита, БД или внешнем реестре).

## ⚠️ Известные ограничения

1. **Зависимость от этапа извлечения (Extraction Dependency):** Конвейер BUKVA-49 работает детерминированно над структурированными данными (`TaskSpecification` / JSON). Если языковая модель или модуль извлечения пропустили неявное ограничение, галлюцинировали несуществующее условие или неверно считали цену из PDF/скана документации, ядро не может верифицировать то, что не передано в контекст. Рекомендуется использовать конфигурации со строгой валидацией цитат из текста (`quoted_constraints`) и эталонную верификацию двумя независимыми разметчиками.
2. **Ложные отказы при разборе сырого текста (Fail-Closed False Rejections):** При использовании текстового интерфейса `run(task_text, ...)` конвейер строго следует правилу Fail-Closed: при малейшей неоднозначности ограничений по срокам закупка отклоняется во избежание ложноположительной сертификации. Из-за этого возможны ложные отказы на нестандартных текстовых формулировках:
   * Числительные словами (*«не более пяти суток»* вместо цифры *«5»*);
   * Дефисные или составные конструкции (*«5-дневный срок»*, *«срок - 5 календарных дней»*);
   * Семантически смежные числа в тексте (*«Ограничений по срокам нет. Оплата в течение 10 дней»* — число 10 из условия оплаты блокирует эвристику отрицания срока поставки).  
   *Для промышленных интеграций рекомендуется использовать типизированный интерфейс данных `run_spec(spec)`*, который полностью исключает хрупкость регулярных выражений.
3. **Линейность базового графа:** Базовые формулы выполняются строго последовательно. Ветвления и условные циклы реализуются на уровне мета-автомата.
